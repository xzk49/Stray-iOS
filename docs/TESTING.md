# 已测范围与剩余问题

截至 2026-10-03，当前源码对应本地实验版 **v21**。这是人工真机与本地回归测试记录，源代码 CI 不会运行商业游戏。未经测试的项目保持待验证。

## 真机

设备为 iPhone 17（A19、8 GB），系统 iOS 26.3。发布整理环境为 Apple Silicon Mac / Xcode 26.6。原始游戏版本固定为 1.6 (102)。

## 图形与性能

- v17 Dead City 的一个观察位置：实际纹理池 2 GiB，247 个近期资产没有低于 wanted mip；主要 GroundDirt01 与管道色彩/法线贴图驻留 12 mip。这只证明该位置的纹理驻留，不证明材质正确或全关卡覆盖。
- 菜单猫：原生抓帧显示毛发绑定 2048×2048、顶点为有限值，深度轮廓平滑；最终猫仍有块状异常。禁用阴影可改善边界但令光照不正确，不能作为完整修复。
- 地面、水、管道仍存在用户观察到的材质问题。
- v18 900p 热机样本：提交约 **10.55 帧/秒**，25 秒记录全程 Serious 热状态；不是冷机基线。同步 Metal pipeline 创建约 617–707 ms，附近观察到 1571 ms 帧间隔。
- v21 720p 热机 300 帧窗口：提交约 **10.67 帧/秒**，间隔 p50 89.6 ms、p95 136.9 ms、最大 376.5 ms；内存 footprint 约 4181 MiB。
- 这些为 drawable 提交/间隔样本，不是完整 GPU 执行时长测量。**720p60、900p40–50 尚未验证。**

## 电影适配

三组原始 4K/1080p 电影：

- `Bink_InsideTheWall_Falling_ZONE`
- `Bink_EndCineOpeningCity`
- `Bink_JailToMidtown`

路由只作用于指定 Movies 目录和这三个精确名称。检查 44 字节 KB2n 头、文件长度、3840×2160/1920×1080 尺寸、帧数、帧率、标志及音轨字段后才选择 1080p；失败时保留原路由。原始电影保持不变。

实际配对和错误头/缺失资源测试通过。选择减少 75% 解码像素，但**原生电影路由触发、播放卡顿改善、音画同步与相关缓冲区故障路径尚未完成复测**。

## 已验证的本地 v21 归档

既有私人完整资源归档约 8,370,038,266 字节：

- 签名严格验证通过。
- ZIP CRC、58 个文件的 SHA-256 通过。
- 16 个原始资源、25 个 frameworks、3 个 Bink 库通过。
- 三个已记录的 CPU 策略通过，无其他主镜像 `__text` 变更。

此记录对应既有真机候选。2026-10-03 另用本仓库统一命令从原始输入完成 prepare → build → check → package：29 个输入哈希、16 个资源、57 个归档文件、25 个 frameworks、三个 Bink 库和三个 CPU 策略均通过；严格签名与 ZIP CRC 通过。37 个运行时源文件与既有 v21 一致。新构建归档 8,370,036,490 字节，没有再次安装或进行新的真机游戏测试。机器可读记录见 [build-verification-v21.json](build-verification-v21.json)。任意使用者仍需验证自己的本地构建与设备。
